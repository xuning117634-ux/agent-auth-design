# 应用交互模式变化带来的安全真空：第 4 页问题拆解一提示词

## 使用方式

目标是生成一页 16:9 中文企业汇报 PPT 图：完整页面结构、纯白背景、蓝紫科技风，颜色只进入明确框框、卡片、标签或节点内部。页面需要和前三页保持一致风格，重点讲清楚第一个问题：Agent 资源访问方式如果沿用机机直连，会带来越权、凭证扩散和审计绕行；解决方案是把资源访问收敛到 MCP 网关，经过 MCP 安全沙箱后再由人机 API 按用户权限访问数据。

- 除节点、标签、风险卡片、方案卡片、结论带等“框框”内部之外，其余所有区域都必须保持纯白色。

- `MCP 网关`、`MCP 安全沙箱`、`人机 API` 必须依次出现，不要合并成一个泛泛的 MCP 标签。
- `集中鉴权` 和 `统一审计` 作为小型胶囊标签放在 `MCP 网关` 附近。

## 风险拆解

在左侧禁止路径周围放 4 个以内的风险标签，全部放在明确边界的卡片或警示框中：

```text
越权调用

凭证扩散
机机凭据被 Agent 复用或传播

数据越权
资源侧难按用户权限收敛数据

审计绕行

```

风险标签样式：
- 使用浅橙或浅红橙警示卡片，颜色必须只在卡片内部。
- 每个风险标签最多两行：第一行风险名，第二行短解释。
- 不要增加第五个风险点。
- 不要写长段落，不要把风险标签压住主链路。

- 所有需要背景颜色渲染的地方，都必须有明确框框承载，可以是卡片式、胶囊式、节点式或其他合适风格，并且只在框框内部做背景颜色渲染。

- 如果需要阴影，只能非常轻微，不能让框框外的背景看起来变灰或有色。

## 视觉风格

- 背景：纯白色 `#FFFFFF`。
- 主色：蓝色、紫色、青色渐变，延续前三页。

- 治理色：蓝色、青色或绿色，只用于右侧合规路径、方案卡片和结论带内部。

- 节点：现代圆角，优先无阴影，保持干净。

不要让页面变成说明书截图。图要像正式 PPT 中的抽象访问链路治理图，而不是系统设计文档截屏。

## 与前 3 页的承接

第 1 页说明传统模式下：

```text
用户 -> 应用 -> API -> 数据库
身份明确 · 逻辑固定 · 边界稳定
```

第 2 页说明智能体模式下：

```text
用户 -> Agent -> 应用 -> API -> 数据库
执行主体被拆分 · 调用凭据被复用 · 授权与审计出现断点
```

第 3 页说明风险建模：

```text
授权范围、AI 代理执行范围、用户自主调用范围必须收敛
② > ① 或 ② > ③ 都会产生风险
```

第 4 页进入问题拆解一，聚焦资源访问方式：

```text
不能让 Agent 沿用机机直连资源
必须改造为人机鉴权
必须先进入 MCP 网关，再经 MCP 安全沙箱到人机 API 访问数据
```

本页不是新增复杂业务场景，而是把第 2 页中的 `机机 API` 风险和第 3 页中的权限收敛原则，落到第一项治理动作：资源访问链路改造。
