- 参考图 2：治理目标文字，用来提取“无授权不可自行操作、权限最小化、不可放大主体权限”的目标表达。

## 可直接复制的提示词

请基于我上传的两张参考图，生成一页 16:9 中文企业汇报 PPT 页面。

```text
Agent 安全风险建模：授权范围、执行范围与主体权限必须收敛
```

副标题：

```text
Agent 不能因具备工具能力就自行操作，所有执行都必须落在用户授权、最小权限和主体权限边界内。
```

重要要求：

- 保持前两页材料的完整页面结构：顶部有小标题标识、主标题和副标题。
- 左上放小标题标识：`03 / 风险建模`。
- 画布背景必须是纯白色 `#FFFFFF`。
- 除节点、标签、风险卡片、原则标签、结论带等“框框”内部之外，其余所有区域都必须保持纯白色。
- 不要使用整页浅灰、浅蓝、渐变、纹理、色块背景或大面积背景面板。
- 所有背景色、色块、渐变和警示色都必须收进明确边界的框框、卡片、标签或节点中。
- 不要复刻参考图 1 的大段说明文字，只保留范围关系和关键挑战。

这是一页风险建模分析页。不要做复杂业务场景，不要讲具体应用案例，只用一个简洁模型图说明：用户授权任务范围、AI 代理执行范围、用户自主调用范围之间如果不一致，就会产生未授权操作和权限放大风险。

## 核心图示

主图重画为简洁模型，不要照搬参考图 1 的黑白说明书样式。

模型结构：

```text
用户 -> Agent -> 应用 / API / 数据
```

三段范围文字必须放进对应箭头内部：

```text
① 用户授权任务范围
② AI 代理执行范围
③ 用户自主调用范围
```

也就是说，`用户授权任务范围`、`AI 代理执行范围`、`用户自主调用范围` 都不能作为独立节点文字漂在外面，必须写在箭头里。

图示要求：

- 左侧是 `用户`，用用户图标或授权卡片表示。
- 中间是 `Agent`，用蓝紫渐变圆角矩形或卡片表示。
- 右侧是 `应用 / API / 数据`，用 3 个小节点或一个组合节点表示。
- `用户 -> Agent` 的箭头内部写 `① 用户授权任务范围`。
- `Agent -> 应用 / API / 数据` 的箭头内部写 `② AI 代理执行范围`。
- 上方从 `用户` 跨到 `应用 / API / 数据` 的轻量弧形箭头内部写 `③ 用户自主调用范围`。
- 可以在 `② AI 代理执行范围` 箭头附近用小标签标注 `工具调用 / MCP`，但不要让它抢主视觉。
- 图中必须呈现两个风险关系：`② > ①` 和 `② > ③`。
- 模型图保持清爽，连线少，关系一眼可读。

## 风险建模

在主图下方或两侧放 2 个风险卡片，每个卡片最多两行解释：

```text
风险一：执行与授权不一致
② > ①：Agent 可能执行未授权操作

风险二：代理与人权限不一致
② > ③：Agent 可调工具超出主体原本权限
```

风险卡片样式：

- 使用浅橙或浅红橙警示卡片，但颜色必须在卡片内部。
- 每张风险卡片用短标题 + 一个不等式 + 一句解释。
- 风险一必须出现 `② > ①`。
- 风险二必须出现 `② > ③`。
- 不要加入代码审查、数据外发、具体业务查询等案例。
- 不要使用长段落。

## 治理目标

在底部放 3 个原则标签，可以用横向胶囊标签或轻量卡片表达：

```text
Agent 无授权不可自行操作
Agent 权限最小化
不可越权放大主体权限
```

可以在原则标签旁边或上方补充一个小标签：

```text
一事一时一次授权
```

治理目标表达要求：

- 三个原则标签必须清晰可见。
- `一事一时一次授权` 只作为小标签，不展开成长段文字。
- 底部原则与主图、风险卡片之间要有层次，不要挤在一起。

## 页面布局

顶部：

- 副标题使用深灰色中号文字，一行或两行以内。

中部：

- 主视觉是一个简洁范围模型图。

- 三段范围文字必须写在箭头内部：`① 用户授权任务范围`、`② AI 代理执行范围`、`③ 用户自主调用范围`。
- 上方弧形箭头 `③ 用户自主调用范围` 不要太粗，不要喧宾夺主。

## 白底与框内颜色规则

必须严格执行：

- 整个画布背景是纯白色 `#FFFFFF`。
- 所有框框外部区域保持纯白色。
- 背景色、色块、渐变、警示色等颜色渲染只允许出现在框框内部、节点内部、标签内部、图标内部、箭头和边框上。
- 所有需要背景颜色渲染的地方，都必须有明确框框承载，可以是卡片式、胶囊式、节点式或其他合适风格，并且只在框框内部做背景颜色渲染。
- 模型节点、风险卡片、原则标签、结论标签可以各自使用独立浅色或渐变填充。
- 不要使用外发光、重投影、玻璃拟态、背景光斑、渐变底板或整页色块。
- 如需阴影，只能非常轻微，不能让框框外的背景看起来变灰或有色。

## 视觉风格

- 背景：纯白色 `#FFFFFF`。
- 主色：蓝色、紫色、青色渐变，延续前两页。
- 风险色：橙色或红橙色，只用于风险卡片内部。
- 治理原则：可以使用浅青、浅蓝或浅绿色标签，但必须在框内。
- 文字：深蓝或深灰。
- 节点：现代圆角，优先无阴影，保持干净。
- 整体：科技感、企业汇报风、低信息噪音。

不要让页面变成说明书截图。图要像正式 PPT 中的抽象风险模型图，而不是培训材料截图。

```text

人机API 复用用户Cookie
```

本页“风险建模”需要进一步回答：

```text

越过授权、执行、主体权限交集的操作都应被拒绝
```
