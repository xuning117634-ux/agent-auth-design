## 核心图示




右侧输出保留三态决策：

```text
ALLOW
AUTHORIZATION_REQUIRED
DENY
```

右侧三态输出要求：
- `ALLOW` 使用绿色框，表示权限交集和策略校验均通过。
- `AUTHORIZATION_REQUIRED` 使用橙色框，旁边或下方放小标签：`高危工具需要人工确认`。
- `DENY` 使用红色框，表示越过权限交集、授权模式或策略约束时拒绝。
- 三个输出节点纵向排列或轻微错位排列，箭头从中心节点指向右侧输出，线条少而清晰。
- 不要把 `AUTHORIZATION_REQUIRED` 解释成最终允许，它只表示需要人工确认后再重新判断。

主图画法要求：
- 中心节点使用蓝紫渐变卡片或大节点，是页面视觉中心。
- 中心节点上半部分写 `Agent 权限策略中心`，可配一个白色盾牌/锁图标。
- 中心节点下半部分保留白色内嵌公式框，公式分三行排版：`最终权限 = 用户权限 ∩`、`Agent操作权限 ∩`、`任务被授予的权限`。
- 4 个约束标签围绕中心节点分布，使用浅蓝、浅青、浅紫或浅绿卡片，颜色必须在卡片框内。
- 右侧只保留三态输出，不再绘制左侧输入卡片。
- 箭头数量要少，不要交叉，不要让连线穿过文字。

## 与前 5 页的承接

第 4 页进入问题拆解一，聚焦资源访问方式：

```text
不能让 Agent 沿用机机直连资源
必须改造为人机鉴权
必须先进入 MCP 网关，再经 MCP 安全沙箱到人机 API 访问数据
```

第 5 页进入问题拆解二，聚焦凭证委托方式：

```text
不能让 Agent 拿到用户完整 Cookie
必须由 Agent 网关拦截隔离 Cookie
临时受控Token代表用户委托授权给Agent的工具调用范围
```

第 6 页进入问题拆解三，聚焦精细化委托控制：

```text
不能只判断工具是否可达
必须保留 RBAC ∩ PBAC 权限交集
高危工具需要人工确认
```

本页不是重新讲凭证隔离或 MCP 接入，也不是展开策略中心详细方案，而是把 Agent 调工具前的授权边界抽象成一条核心原则：权限取交集，高风险必须人工确认。
